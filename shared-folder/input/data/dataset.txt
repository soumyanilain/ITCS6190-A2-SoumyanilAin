Doc01 Cloud computing delivers computing resources over the internet on demand. Instead of buying servers, an organization rents virtual machines, storage and networking from a provider and pays only for what it uses. Elasticity lets the system grow and shrink with the workload.
Doc02 Virtualization is the technology that makes cloud computing possible. A hypervisor runs several virtual machines on one physical server, each with its own operating system. Because the machines are isolated, a provider can share hardware safely among many customers.
Doc03 Containers package an application together with its libraries and configuration so that it runs the same way on every machine. Unlike virtual machines, containers share the host operating system kernel, which makes them small and fast to start. Docker is the most popular container platform.
Doc04 Docker Compose describes a multi-container application in a single YAML file. Each service gets its own image, environment variables and volumes, and Compose starts them together with one command. Containers on the same Compose network reach each other by service name.
Doc05 Hadoop is a framework for storing and processing big data on clusters of commodity machines. HDFS splits every file into large blocks and replicates each block on several DataNodes, so the data survives when a machine fails. The NameNode keeps the directory tree and knows where every block lives.
Doc06 MapReduce is a programming model for processing big data in parallel. The map function reads a split of the input and emits key-value pairs; the framework shuffles and sorts the pairs by key; the reduce function receives every value for one key and emits the result. Hadoop runs MapReduce jobs on YARN.
Doc07 YARN is the resource manager of a Hadoop cluster. The ResourceManager decides which application gets containers, and a NodeManager on every machine starts and monitors them. MapReduce, Spark and other frameworks all request their resources from YARN.
Doc08 Apache Spark is a distributed processing engine that keeps data in memory between operations, so iterative algorithms run much faster than with MapReduce. A Spark job is a graph of transformations on resilient distributed datasets, and the driver schedules it across executors on the cluster.
Doc09 Spark DataFrames organize distributed data into named columns, like a table in a relational database. Spark SQL lets you query a DataFrame with SQL, and the Catalyst optimizer rewrites the query into an efficient plan before the executors run it.
Doc10 Structured Streaming treats a live data stream as a table that grows without end. Each micro-batch of new records is processed with the same DataFrame operations used for static data, and the results are written to a sink such as a file, a database or a dashboard.
Doc11 Machine learning on big data needs a distributed library. Spark MLlib provides algorithms for classification, regression and clustering that scale across a cluster, and pipelines that chain feature transformers and a model together so the same steps run on training and on new data.
Doc12 Amazon Web Services offers computing, storage and database services in the cloud. EC2 provides virtual machines, S3 stores objects, and EMR runs Hadoop and Spark clusters on demand. A data pipeline on AWS often reads from S3, processes the data with Spark, and writes the results back to S3.
